# The judged half, measured at last — 2026-09-12

**16/16 on every arm, and the judge passed 16 of 16 controls including 8 it had
to call *different*.**

| arm | GRADED | JUDGED |
|---|---:|---:|
| raw (reference) | 75/75 | **16/16** |
| compressed | 75/75 | **16/16** |
| stored | 73/75 | **16/16** |

`JUDGED not measured` had printed on every run since `src/eval_model.py` was
written. It is gone.

## Why it was never measured, and why it did not need to stay that way

Judging needed `JUDGE_MODEL`, and this project does not buy quota. That was the
whole obstacle — and it turned out the expensive half had already been done for
free: `--emit` has been writing the 16 comprehension questions into every reading
task since it was built, readers have been answering them, and `--grade` stored
those answers and scored nothing. **No run file in `data/eval_runs/` had ever
contained the string `same_as_raw`.** The prose was sitting there.

So the judging takes the same road the reading already took: `--emit-judge`
writes one blinded comparison per judged answer, fresh subagents rule on them,
`--judge-in` folds the verdicts back into the run file. The run-file format did
not change — `summarise()` only ever needed a boolean `same_as_raw` per record.

## What the judge is asked

Not "which is correct". **"Do these two say the same thing?"** — because the claim
under test is that answers do not *move*. If raw got something wrong and
compressed got it wrong the same way, compression cost nothing, which is what
this project actually promises.

## The blinding, and the leak found while building it

The API judge's prompt says: *"The first was produced from the original data; the
second from a compressed form of it."* Fine for a paid model that will never see
anything else; a loud hint to a subagent about which side to prefer. The emitted
task says neither, labels the two answers **A and B**, and randomises which side
is the reference.

That was not enough. **The first version named its task files
`<payload>__<question>__<arm>.md`** — so a judge reading its own filename learned
the arm, the exact leak that had just been taken out of the prompt, left in the
one place nobody looked. Tasks are `judge_001.md` now, and the mapping lives only
in `_judge_truth.json`.

## The first run was worthless, and the controls are why we know

The first judged pass came back **"same" 18 times out of 18**. That is either a
real result or a judge that cannot say "different", and nothing in the run could
tell the two apart — `docs/harness.md` Rule 14 in a new suit: *a detector nobody
has shown a positive to is not a detector.*

So the emit step now interleaves **controls**, indistinguishable from real pairs:

| kind | built from | must read |
|---|---|---|
| same | one raw answer against itself | `same` |
| different | two raw answers to **different questions** about the same payload | `different` |

`--judge-in` checks them **before writing anything**, and a failed control
produces no judged number at all — the move `RAW_MIN_GRADED_FRACTION` already
makes for the reading half: a comparison against a reference that has itself
collapsed is not a comparison.

Shown a positive, as Rule 14 demands: one control verdict was deliberately
flipped and the ingest refused with exit 2, naming the task.

**With controls in place the judge scored 16/16 on them — 8 of those pairs it had
to call different — and 16/16 on the real questions.** The number above means
something it did not mean an hour earlier.

## The weakness, stated rather than buried

**The judge and the answerer are the same model family.** An independent judge
from another vendor would be the stronger instrument, and this is not that. The
controls show this judge can tell apart answers to different questions; they do
**not** show it is free of a shared prior with the model whose work it is marking.

Two things bound what may be claimed. It is asked only whether two answers say
the same thing, never which is right — a narrower question, with less room for a
shared prior to operate in. And `JUDGED_ALLOWED_GAP = 1` was set long before any
of this, on the reasoning that an LLM judge over 16 questions cannot resolve
better than that.

`docs/cold-reads.md` already says read #5's automated kind does not replace reads
#1–#4. Same shape: this measures something real and it is the weaker instrument.

## What it did not change

The stored arm is still **73/75 graded** and the run still says
`THRESHOLDS NOT MET`. The judged half passing does not offset a graded failure
and is not reported as though it does — the two misses are the counting finding
in `docs/cold-reads/2026-09-12-miscount.md`, still open.

## Three checks this bought

- `self_test()` grew from 6 cases to 9. `_fake_run` hardcoded `"judged": []`, so
  every judged failure mode was unreachable from the one thing that guards the
  verdict. The case that matters: **if raw never records `same_as_raw`, its
  judged_ok is 0, every gap goes negative, and every arm PASSes against nothing.**
- `inconclusive_reasons()` gained a judged-denominator condition. It inspected
  only the graded half, so a judge pass covering three payloads out of eight
  would have printed a clean gap off a third of the data.
- The control gate itself, above.
