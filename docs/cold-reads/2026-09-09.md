# Cold read #3, 2026-09-09

Owed by `#dict`, which adds **both** a new format line and a new cell encoding.
Method and running score: [`docs/cold-reads.md`](../cold-reads.md).

One payload this time — `graphql_countries`, the document `#dict` changes most
(two dictionary columns, 250 rows, nulls, nested objects, emoji, CSV-quoted
multi-value cells).

## Result: 11 of 12 correct, confidence 8/10

Highest confidence of the three reads, and **the first factual error**.

`#dict` itself read perfectly. Asked what the `continent.name` cell means, the
reader answered without hesitation: not a continent, a number, and the number is
a lookup into the `#dict` line — then explained it as a shared string table
where "Asia" is written once instead of fifty times. It resolved India's
continent, currency, capital and languages correctly, and correctly reported
`\N` as null for Antarctica's capital and currency.

**The one wrong answer was a count.** Asked roughly how many countries are in
Africa, it hand-counted rows whose continent index was `3` and answered 57
against a true 58. It flagged the risk itself — "a hand count over 250 lines can
be off by one".

## The two defects it found, and what changed

### Counting an unmarked list is a lookup you cannot verify

Asked for India's languages, the reader had to count 61 entries into an 11KB
single-line JSON array. It got the right answer, and said plainly why that was
luck: it cross-checked neighbouring countries because there is "no way to
*verify* an index". Its own suggested fix was periodic index markers.

**This is the third cold read in a row whose weak point was counting**, and the
first where the count actually came out wrong:

| | what nearly went wrong |
|---|---|
| #1 | drifted across a run of empty cells |
| #2 | miscounted 13 positional columns; caught it by recounting |
| #3 | could not verify an index 61 deep; **miscounted 58 as 57** |

So the `#dict` line is now an **object keyed by index** rather than a bare list:
`{"0":"Europe","1":"Asia",...}`. The lookup becomes direct — read the key, no
counting — and it can be confirmed rather than trusted.

Measured cost: **+151 tokens across the sample set, +0.2%.** The same trade
`HEADER_REPEAT_EVERY` made at +0.3% for the same underlying reason, and the same
principle: a reader that has to count is a reader that will eventually miscount.

### The repeated header was never explained

The reader called this "the single most dangerous thing in the document". The
`[250]{...}` line appears seven times and nothing said whether that is one table
reprinted for legibility or seven tables of 250 records. **A reader taking the
second meaning answers 1,750.** It resolved this only by counting 256 lines and
subtracting six repeats — arithmetic the document should not have required, and
the very next thing it counted came out wrong.

The repeat exists because cold reads #1 and #2 both drifted counting columns
against a distant header, so removing it would reintroduce the older bug. It is
now stated in the legend instead: *"the [N]{...} header repeats every 40 rows;
it is one table, not a new one."*

## Recorded, not fixed

Real findings, all pre-dating `#dict`, none acted on yet:

- **CSV quoting is used but never documented.** `"BOB,BOV"` is quoted because it
  contains a comma; nothing in the document says so. The reader inferred CSV
  rules from general knowledge — precisely what a cold read exists to expose.
- **Multi-value cells are semantically ambiguous.** Is `"BOB,BOV"` one string or
  a joined list? The header says `str`, but `languages` *is* a list, so the
  question is fair and round-trip-relevant.
- **Cells are positional and that is never stated.** The `{...}` header looks
  like a set of typed keys, not an ordered list. Verifiable here only because
  currency codes are recognisable.
- **`?` is undefined.** Read as "nullable" by inference from where `\N` appears.
- **No escape for a literal `\N` is documented** (one exists — `str` values
  beginning with a backslash are doubled — but the document never says so).
- The `#dict` line uses `\uXXXX` escapes while the rows carry raw UTF-8.

Each is a legend entry's worth of tokens. None caused a wrong answer in three
reads, so they wait for evidence rather than being fixed on suspicion — the same
standard every other threshold here is held to.
