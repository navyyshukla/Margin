## Confidence: 6/10 — and that is the finding

Every answer was right, but the reader was not sure they were, and the reason is
specific and fixable.

**Runs of consecutive empty cells (`,,,,`) cannot be counted reliably by eye.**
On A7 the reader first concluded a second story had no url, having miscounted
the empty fields before `none`. It caught the error on a slower pass only by
cross-checking against domain knowledge that the post was a link post. Its own
words: caught "by luck".

Other points raised, in its order of severity:

1. **Empty-cell runs are miscountable.** The one that caused an actual error.
2. **`\N` (null) vs empty (absent) is never stated.** `\N` is in the legend;
   the convention that an empty cell means "key absent in this row" is left to
   be inferred. This distinction is load-bearing — it is how Q4/Q10 tell PRs
   from plain issues.
3. **`dints` does not say whether the first token is absolute.** The example
   makes it inferable, but only by inference.
4. **`#wrap` and `#const` are dense inline JSON** with no hint that they are
   envelope metadata rather than per-row data.

## What this changes

Fixed immediately (cheap, no ambiguity about the right answer):

- Legend now spells out that an empty cell means the key is absent, and that the
  first `dints` token is absolute.

**Decided 2026-09-08: legend only, no visible marker.** A marker for absent
cells would make runs countable, and both options were measured on both
payloads first:

| option | github_issues | hn_stories | new escaping rule? |
|---|---|---|---|
| legend only | +0 | +0 | no |
| `\M` | +351 (1.5%) | +194 (1.0%) | no — the `\`-prefix escape covers it |
| `-` | +147 (0.6%) | +78 (0.4%) | **yes**, for the literal string `-` |

Not taken because the reader got all 13 answers right, so this buys confidence
rather than correctness — and the cheaper option needs a new escaping rule for
a very common string value, which is where two of this project's bugs have
already come from. 204 absent cells on GitHub and 116 on HN, if the numbers
need re-deriving.

**Revisit if** a future cold read produces an actual wrong answer from an
empty-run miscount, rather than a caught near-miss. At that point it stops
being a confidence question. `\M` is the option to reach for — a percent is
cheap next to a wrong answer, and it adds no new escaping.
