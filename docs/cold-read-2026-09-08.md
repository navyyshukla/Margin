# Cold read, 2026-09-08

The one check no code performs: can a model that has never seen this project
read a `#margin/v1` document correctly?

The eval harness runs its checks on *decompressed* data, so it never reads the
document at all. Claude's own reading does not count — it designed the format
and knows what every marker means without being told.

## Method

A fresh reader, given only the two rendered `.txt` documents and told:

- read nothing else — no source, no docs, no original JSON
- write no code to parse them; read as a prompt is read
- answer "not answerable from this document" rather than guess
- say bluntly what was ambiguous

Questions: the eval set from `data/eval_questions.md`, plus the `dints` trap
(decode a delta-encoded array) and the adversarial `avatar_url` question.

**A5 is the one that mattered.** The reader hit the `dints` column, went to the
`#legend` line, applied the cumulative sum, and got all five IDs right. Without
that line it would have read `16582146 6 3 2` as literal comment IDs and been
confidently wrong. The legend costs 44 tokens and is the reason this row is a
tick.

**B3 is the second.** Asked for a field that boilerplate-stripping removed, the
reader declined instead of inventing a plausible `avatars.githubusercontent.com`
URL. Stripping does not induce hallucination.

## Confidence: 6/10 — and that is the finding

Every answer was right, but the reader was not sure they were, and the reason is
specific and fixable.

**Runs of consecutive empty cells (`,,,,`) cannot be counted reliably by eye.**
On A7 the reader first concluded a second story had no url, having miscounted
the empty fields before `none`. It caught the error on a slower pass only by
cross-checking against domain knowledge that the post was a link post. Its own
words: caught "by luck".

Other points raised, in its order of severity:

1. **Empty-cell runs are miscountable.** The one that caused an actual error.
2. **`\N` (null) vs empty (absent) is never stated.** `\N` is in the legend;
   the convention that an empty cell means "key absent in this row" is left to
   be inferred. This distinction is load-bearing — it is how Q4/Q10 tell PRs
   from plain issues.
3. **`dints` does not say whether the first token is absolute.** The example
   makes it inferable, but only by inference.
4. **`#wrap` and `#const` are dense inline JSON** with no hint that they are
   envelope metadata rather than per-row data.

## What this changes

Fixed immediately (cheap, no ambiguity about the right answer):

- Legend now spells out that an empty cell means the key is absent, and that the
  first `dints` token is absolute.

**Open, and the real decision:** the empty-run problem. A visible marker for
absent cells (`,-,-,-,` instead of `,,,,`) would make runs countable, at a cost
of roughly one character per absent cell. That is a token cost against a
legibility gain, and legibility is the constraint this phase is held to — so it
needs measuring on both payloads before it is chosen, not guessing.

## Standing rule

Re-run this whenever a **new cell encoding** is added. A new encoding is exactly
the thing a reader cannot infer, and it is invisible to every automated gate.
